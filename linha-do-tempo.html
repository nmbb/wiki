REGISTO DAS EXPERIÊNCIAS

O que aconteceu em cada teste.

1996 · CONFIRMADO

Windows NT 4.0

Domínio LABNT40, controladores NT4 e estação de trabalho. Os testes de acesso à partilha Samba do Red Hat confirmaram leitura e escrita, incluindo a pasta criada a partir do Windows.

Ver experiências NT4 →
2000 · INSTALAÇÃO FALHADA

Red Hat Linux 6.2

O instalador Anaconda terminou com uma exceção associada a getCompsList(). Não se concluiu a instalação nem se identificou uma causa definitiva.

Ver Linux Retro →
2000 · CONFIRMADO

Windows 2000

Instalação e autenticação verificadas. A VM foi usada para abrir uma partilha pessoal do Samba no SuSE Linux 9.0. A validação de permissões da pasta COMUM ficou incompleta.

Ver teste Samba →
2001 · FUNCIONAL

Red Hat Linux 7.1

Kernel 2.4.2-2 e Samba 2.0.7. Ligação através da vmbr70, correção da resolução de hostname e pasta ALUNOS acessível com escrita a partir do Windows NT 4.0.

Ver capturas e comandos →
2001 · INSTALAÇÃO FALHADA

Caldera OpenLinux Server 3.1

Detetou dispositivos PCI, CD-ROM e placa Ethernet, mas o LIZARD apresentou problemas e ficou bloqueado ao preparar o particionamento. A instalação não foi concluída.

Contexto do laboratório →
2003 · PARCIALMENTE VALIDADO

SuSE Linux 9.0

Instalação concluída pelo YaST, rede virtual vmbr71 e SSH verificados. Samba 2.2.8a respondeu ao Windows 2000. A pasta COMUM apresentou NT_STATUS_BAD_NETWORK_NAME.

Ler artigo completo →
2009 · INSTALADO

Windows Server 2008 R2

Instalação e captura do ecrã de início de sessão documentadas. Não foram confirmados testes adicionais de gestão de utilizadores ou serviços de domínio.

Ver notas Windows →

SuSE Linux 5.2 / 6.0

Obtiveram-se imagens ISO históricas, mas não existe confirmação de instalação ou de testes funcionais destas versões. Não são assinaladas como falhadas.
